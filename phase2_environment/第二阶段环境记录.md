## 安装与复核方法

1. WaCSim 源码位于 `D:\2026\WaCSim`。从 `https://github.com/StavC/WaCSim` 获取源码并检出上述完整提交；改造时保留原始 CTown 配置作为对照。
2. 在 Windows 上使用 Docker Desktop 的 WSL2 Linux 引擎。当前机器的数据目录位于 `D:\2026\DockerData\wsl`，Docker Desktop 必须通过 `D:\2026\DockerData\Launch-DockerDesktop.vbs` 启动，以沿用 D 盘 AppData 路径；直接运行 `Docker Desktop.exe` 会使用本机加密的 C 盘 AppData，触发设置文件 `rename` 跨盘错误。
3. 本目录的 `phase2.Dockerfile` 是已运行镜像采用的环境适配定义。以 `D:\2026\WaCSim` 为构建上下文重新构建：

   ```powershell
   docker build -t wacsim:fd404fc -f D:\2026\WaCSim\phase2_environment\phase2.Dockerfile D:\2026\WaCSim
   ```

4. 运行只读环境探针：

   ```powershell
   docker run --rm --entrypoint python3 --mount "type=bind,source=D:\2026\WaCSim,target=/wacsim,readonly" wacsim:fd404fc /wacsim/phase2_environment/phase2_environment_probe.py
   ```

5. 核对输出 JSON 中所有 `modules.*.ok`、`tools.*.ok`、`epanet_smoke.ok` 和 `wntr_smoke.ok` 均为 `true`，再与 `phase2-environment.json` 的版本和镜像 ID 比较。完整 WaCSim 网络仿真需按原示例以 `--privileged` 运行；上述探针无需特权。

## 复现边界

- `phase2.Dockerfile` 的基础 Ubuntu 镜像已固定摘要；部分 apt/Python 包及 MiniCPS、Mininet、epynet 的上游 Git 依赖未固定提交。未来从 Dockerfile 重新构建可能得到不同依赖版本。正式实验以当前镜像 ID、源码提交和 `phase2-pip-freeze.txt` 为环境基准，任何重建都须重新核对版本与测试结果。
- `phase2-pip-freeze.txt` 中有构建时的 `file:///tmp/...` 路径，不能单独用 `pip install -r` 复现；应使用 Dockerfile。只读挂载覆盖了镜像内的 `wacsim.egg-info`，所以探针中的 `packages.wacsim` 为 `null`；无挂载执行 `pip show wacsim` 显示 1.1.1。
- 9.1 仅说明环境可用。第一阶段评审及独立 Git 提交尚待完成；9.2 合约与快速 EPANET 无攻击回放入口已实现，后续攻击回放与正式校准尚未完成。
