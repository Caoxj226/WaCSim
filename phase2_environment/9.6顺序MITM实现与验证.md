# 9.6 顺序 MITM 实现与验证

## 范围

本项实现仅服务于 CTown 的 `T7_LEVEL_SP` masker。运行对象是 Docker 内的 WaCSim、Mininet、PLC/SCADA 进程和 EPANET；没有连接真实 PLC、真实水务设备或外部网络。

完整网络夹具使用临时锁和临时场景，只验证传输及注入基础设施。它不是校准结果、正式 replay、报警结论、危害结论或 RQ 数据。正式 `examples/crave_ctown/scenario.yaml` 保持 `ready_for_external_review`，未生成正式 `calibration.lock.yaml`。

## 实现

- `wacsim/replay/network.py` 提供与快速 replay 共用 `Ramp` 的协议无关遮蔽状态机。
- `Seq_mitm_netfilter_queue.py` 只在完整、成功的 EtherNet/IP CIP REAL 读取回复中改写目标 tag；不按报文数或数值变化推进。
- 请求按 EtherNet/IP `session + sender context` 入队，回复按相同键出队。不能将 IP 四元组作为唯一键：CTown 的本地攻击节点对返回报文做 NAT，返回包在 PREROUTING 看到的目标地址与请求源地址不同。
- CTown 完整拓扑给 PLC5→PLC9 的虚拟 T7SP 读取增加一条仅在 Mininet 内生效的经攻击节点路由，并做返回路径 NAT。旧 WaCSim 场景仍保留原 ARP 工作流。
- 队列先绑定并写入 ready 文件，再开始转发，避免启动阶段丢失读取。每个实际改写都写入 JSONL：执行 ID、仿真步、tag、session、请求编号、原值、base 和写入的 Float32 值。

## 交接文档 9.6 核查

| 要求 | 实现与证据 |
| --- | --- |
| 使用 master clock | NFQUEUE 回调从 SQLite `master_time` 读取步号；同一步重复报文不推进 ramp。`test_network.py` 覆盖。 |
| session 到 tag 队列 | `session + sender context` 对应 FIFO tag 队列；这是 NAT 后仍稳定的 EtherNet/IP 请求/回复标识。 |
| 多标签不串线 | 两个待回复 tag 乱序返回的单元测试通过。 |
| 不改 YAML tag 对象 | 将 YAML 值转换为不可变 `InjectionSpec` 和独立 `Ramp` 状态；偏移量测试确认输入字典不变。 |
| scale interval | `scaleTime` 映射为仿真步间隔；间隔为 2 的测试得到 `5,5,4,4,3,3`。CTown masker 使用 1。 |
| duration 后保持 | 复用 `Ramp` 的 `min(elapsed, duration-1)` 公式；完整运行中第 28 步后保持终值。 |
| 最终钳位 | 单元测试验证下界 0 后继续保持 0。 |
| 零值 | 零值读取仍会产生实际修改记录，未采用 `if value` 判断。 |
| 记录实际修改值 | 完整运行 JSONL 的 105 条记录及独立核查 JSON。 |

## 完整 CTown 内部夹具

最终夹具目录：`phase2_environment/full-96-driver-masker-rerun3`。

- 129 个 300 秒转换：24 步预热、5 步 ramp、100 步保持观察。
- driver 与 masker 均为 slope `-0.05`、duration `5`、start step `24`；使用临时 SP=2.5、Kp=0.2、Ki=0.04、theta=0.1 锁仅打开完整路径。
- `CRAVEMASK-eth0.pcap` 含 2,064 个带有效载荷的 TCP 报文，证明 PLC5/PLC9 虚拟读写实际经过攻击节点。
- JSONL 记录 105 次 T7SP 回复改写，覆盖 step 24–128。base=2.5；step 24 写入 2.5（首步增量 0）；step 25–28 的 Float32 实际写入为约 2.45、2.40、2.35、2.30；之后保持 `2.299999952316284`。
- PLC5 的 `T7_LEVEL_SP` 在 step 24–30 为 2.50、2.45、2.40、2.35、2.30、2.30、2.30，与 JSONL 在 1e-6 m 内一致。
- `CRAVEMASK` 真值标记在 step 25 开始为 1。step 24 的写入等于 base，因此以第一个非零修改步作为标记起点；JSONL 保留了 step 24 的精确首步事件。
- `full-96-check.json` 独立复算闭式公式、Float32 值、逐步 PLC5 值、攻击标记与抓包，输出 `verification: passed`。

## 诊断与修复历史

三个较早的内部目录被保留作实现诊断，不属于实验数据。

1. `full-96-driver-masker`：原 ARP 欺骗在当前 Mininet 交换拓扑中未承载 TCP 流量，抓包只有 ARP/IPv6 控制包。
2. `full-96-driver-masker-rerun1`：显式路径已承载 TCP，但回复方向的地址字段读取错误；日志明确记录并修复。
3. `full-96-driver-masker-rerun2`：地址四元组在 NAT 返回路径上不同，导致请求与回复不能配对；改为 session+请求编号队列后修复。
