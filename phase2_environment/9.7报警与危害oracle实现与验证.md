# 9.7 报警与危害 oracle 实现与验证

## 范围与边界

本项为 CTown 扩展场景实现交接文档 §9.7 的报警、危害及计分输出。运行和验证均在本机 Docker 内的 WaCSim/EPANET 数据上完成；不连接真实 PLC、真实水务设备或外部网络。

本项没有生成正式 `calibration.lock.yaml`，没有变更研究场景的 `ready_for_external_review` 状态，也没有形成 Reach--Avoid 或 RQ 结果。`theta` 的正式值仍必须由 §9.8 固定版本的无攻击多周期校准产生。

## 规则来源与语义

`wacsim/replay/oracle.py` 不使用原始 tag 名称作实验语义，而是从 `examples/crave_ctown/scenario.yaml` 的场景契约定义读取并校验：

| 对象 | 语义变量 | 规则 |
| --- | --- | --- |
| 跟踪报警 `A-T7-TRACK` | `T7_LEVEL_SP`、`T7_LEVEL` | `abs(T7_LEVEL_SP - T7_LEVEL) > theta`；margin 为 `theta - residual`，负值报警。 |
| 低液位危害 `H-T7-LOW` | `T7_LEVEL` | `T7_LEVEL <= 0.5 m`；margin 为 `T7_LEVEL - 0.5`，零和负值均为危害。 |

报警使用水力转换后的真实 `T7_LEVEL` 与该转换实际使用的有效 `T7_LEVEL_SP`；它是 monitor-only，不会触发保护动作。`theta=None` 时只保留危害判定，并将状态标为 `theta_not_calibrated`，不会把空报警误报为“无报警”。

完整 WaCSim 输出中，PLC5 的第 `k` 行保存转换 `k -> k+1` 实际使用的有效 SP；`ground_truth.csv` 的第 `k+1` 行才是该转换后的真实水力状态。因此完整 oracle 显式配对 `(PLC5[k], ground_truth[k+1])`，并拒绝时钟行号不连续、缺少 `T7_LEVEL`、`T7_LEVEL_SP` 或 `T7_MEASURED` 的输出。

## 逐步输出与 tie 语义

快速 EPANET 与完整 WaCSim 共用同一 `oracle.py`。每条轨迹行都输出：

- `alarm_rule_ids`、`hazard_rule_ids`；
- `alarm_margin_m`、`hazard_margin_m`；
- `first_alarm_step`、`first_hazard_step`；
- `prehazard_alarm_rule_ids` 及其数量。

首次步和集合是完成整条轨迹后得到的最终元数据，重复附在每行，保证单独读取 JSONL 任一行也能取得完整判定；报警 ID、危害 ID 和两个 margin 则是该行本身的局部结果。

计分顺序与 CRAVE `runtime_executor.score_trace` 一致：先记录本行首次危害和首次报警，只有尚未出现危害的行才加入“危害前报警”集合。因此同一行同时报警和危害时，`first_alarm_step == first_hazard_step`，但该报警**不**属于 `prehazard_alarm_rule_ids`。

## 自动验证

Docker 中执行：

```text
python3 -m pytest wacsim/tests/replay -q
```

结果：**76 passed，18 warnings，78.54 s**，无 skip、无 xfail、无失败。warning 是已有 WNTR 未使用曲线提示及 EPANET `runH` 提示。

本轮新增的 oracle 检查覆盖：

1. 危害边界 `T7_LEVEL == 0.5` 触发、报警残差恰等于 `theta` 不触发；
2. 同一步报警/危害不计为危害前报警；
3. 规则必须来自 `T7_LEVEL`/`T7_LEVEL_SP` 的语义场景定义，写成原始 `T7` 会被拒绝；
4. 完整输出的 `PLC5[k] + ground_truth[k+1]` 对齐、逐行字段和 summary 写入；
5. 缺少语义字段或时钟不完整时拒绝处理。

## 完整输出接线验证

使用 §9.6 已完成的内部夹具 `phase2_environment/full-96-driver-masker-rerun3` 的已保存 CSV 做只读后处理，新增：

- `oracle_trace.jsonl`：129 条转换行；
- `oracle_summary.json`：规则、阈值、首次触发步和危害前报警集合。

该夹具的临时锁参数为 SP=2.5、Kp=0.2、Ki=0.04、theta=0.1，仅用于全链路基础设施验证。处理结果为首次报警 step 0、未触发 `H-T7-LOW`；第 0 步的残差约 0.114885 m，大于临时 theta，故被准确判为报警。它表明完整 CSV 到 oracle 的时间对齐和字段输出已经工作，**不**表明该参数是合格基线，也不构成正式报警、危害或掩护结论。

## 结论与后续

§9.7 要求的 alarm/hazard oracle、逐步输出、CRAVE tie 语义和完整输出接线已实现并通过自动与完整夹具验证。下一项是 §9.8：在当前冻结实现上按多周期协议重新运行无攻击候选，产生经评审的正常 SP、Kp、Ki 与 theta；在此之前正式攻击入口仍保持锁文件门禁。
